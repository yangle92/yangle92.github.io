# AI 大模型应用开发实战路标

最近拿到一份 AI 大模型应用开发的课程课纲，七个模块、四十多节课。逐行读完发现，它其实不是一份「课程清单」，而是一张**能力地图**——从最底层的提示工程，一路铺到 AI Coding 对研发范式的冲击，中间还夹着部署、并发、微调这些通常被应用开发者跳过的环节。

我把这份课纲整个拆开重排了一遍，整理成下面这份路标。原文表格也放在博客里了，需要对照可以下载。

---

## 一、整体结构：七个模块，一条主线

| 模块 | 课程数 | 主线关键词 |
| --- | --- | --- |
| 模块 1 · AI 大模型基础 | 5 | 提示工程、RAG、多模态、API 调用 |
| 模块 2 · Agent | 8 | Function Calling、MCP、规划反思、多 Agent 协作 |
| 模块 3 · 模型部署及高并发 | 4 | GPU 选型、vLLM、SGLang、KV Cache |
| 模块 4 · 开发框架 | 6 | LangChain、LlamaIndex、AutoGen、HuggingFace、PyTorch |
| 模块 5 · 模型训练与微调 | 6 | LoRA、数据工程、蒸馏、YOLO、多模态 |
| 模块 6 · RAG | 8 | Embedding、混合检索、GraphRAG、Agentic Search、LLM Wiki |
| 模块 7 · AI Coding 带来的范式变革 | 4 | Spec Coding、AI 重构、团队分工、端侧部署 |

七个模块加起来 **41 节课**。有意思的是它的推进方向：不是「由浅入深」的教科书顺序，而是**由应用往底座钻**——先教你怎么用模型，再教你怎么让模型自己干活，然后才回头讲模型怎么部署、怎么微调。走完一圈，你既知道上层怎么写，也知道下层为什么卡。

### 四种课型

课纲给每节课都标了授课形式，统计下来是这样的：

| 课型 | 节数 | 特征 |
| --- | --- | --- |
| 理论知识 | 3 | 概念铺底，打地基 |
| 实操基础 | 2 | 上手跑通 API 与 AI 编程工具 |
| 理论知识 + 案例详解 + 实操 | 24 | 主力课型，讲完就练 |
| 项目实战 | 8 | 完整项目，从零到跑通 |
| 专项求职辅导 | 4 | 简历 + 面试题串讲 |

**「理论 + 案例 + 实操」占了近六成**，这决定了它整体是偏工程而非偏论文的课。而「项目实战」和「专项求职辅导」这两类，是最能看出课程设计意图的地方，后面单独展开。

## 二、逐模块拆解

值得注意的设计：**第一节课就把 RAG 摆到台面上**，而 Agent 幻觉与可控性也在第一模块出现。这两件事——「知识从哪来」和「怎么不胡说」——被当成入门问题，而不是进阶难题。

那个换脸项目很典型：**它不是「AI 项目」，而是「AI 的排队系统」**。真正的难点在于算力怎么分配给成千上万个拆帧任务、失败怎么重试、流量怎么省。这类问题在教程里几乎看不到，但在真实业务里天天遇到。

## 三、八个项目实战

单独把实战项目拎出来看，能更清楚地看到课纲想培养什么能力：

| 项目 | 所属模块 | 练的是 |
| --- | --- | --- |
| OpenManus 开发实战 | Agent | 读框架源码 + 定制角色 + 集成企业知识库 |
| 搭建 Hermes 的长期记忆与自进化能力 | Agent | 记忆系统设计、心跳机制、向量存储与混合检索 |
| 实现 Hermes 的多 Agent 协作与主 Agent 调度 | Agent | 任务拆解分发、子 Agent 注册、通信与结果聚合 |
| 短剧视频逐帧换脸的显卡资源分配及排队系统 | 部署与高并发 | 消息队列解耦、算力排队、超时重试、成本控制 |
| AI 质检 | 训练与微调 | 判别式模型 vs 多模态大模型的正面对比 |
| 企业知识库（RAG 大赛冠军项目） | RAG | 冠军级 RAG 全链路：解析、重排序、父页面检索、指令细化 |
| LLM Wiki | RAG | 用「编译器思路」重做知识库，弱化向量检索 |
| 昇腾 NPU 部署 DeepSeek V4 + 连通 Claude Code | AI Coding | 国产算力部署、量化、推理服务化、Agent 工作流打通 |

八个项目里，**三个是 Agent 方向、两个是 RAG 方向**——这个配比基本反映了当下企业需求的重心：Agent 负责「能干活」，RAG 负责「不胡说」。

## 四、58 道面试题：考点分布

课纲在四个模块末尾各安排了一节求职辅导，一共 **58 道**面试题。这实际上是一份现成的考点清单：

| 模块 | 题量 | 题目风格 |
| --- | --- | --- |
| Agent | 14 | 定义、幻觉、状态管理、自主性与可控性的平衡、项目复盘 |
| 开发框架 | 16 | 框架对比与选型、组件抽象、Memory 机制、PEFT 与 Tokenizer |
| 模型训练与微调 | 17 | 预训练 vs 微调、LoRA 原理、数据从哪来、评估方法、蒸馏 |
| RAG | 11 | 分块策略、架构图、Embedding 选型、混合检索、效果评估与迭代 |

题目里高频出现的几个问题，很能说明用人单位在关心什么：

> 「你如何处理 Agent 的幻觉问题？」
> 「如果你的 RAG 效果很差，你会从哪几个方面去调试？」
> 「你如何评估你微调后的模型效果？」
> 「如果让你从零设计一个 LLM 应用框架，你会如何进行组件抽象？」

**四个模块各有一道「效果怎么评估」类的题**——Agent 评估、RAG 评估、微调评估、检索评估。这不是巧合：能跑通 demo 的人很多，能证明「跑得好」的人很少。

## 五、几点观察

**第一，这条路标是「由用及造」的。** 从提示工程起步，到 Agent，再到部署、框架、微调，最后落到 AI Coding。如果你只有零散时间，按原顺序走没问题；如果想尽快产出，可以「模块 1 → 模块 2 → 模块 6」先打通应用链路，部署与微调留到真正遇到性能瓶颈时再补。

**第二，反复出现的三个主题值得单独标记：** 幻觉与可控性（模块 1、2）、效果评估（四个模块的面试题）、记忆系统（Hermes 两节 + LLM Wiki）。它们贯穿始终，说明这是课程真正想让你带走的东西。

**第三，课纲里两处「自我否定」的课很有价值。** 一处是模块 6 用 Long-Context / Agentic Search / LLM Wiki 挑战 RAG 本身，另一处是模块 3 只讲吞吐与调优、不吹模型能力。愿意讲「什么情况下我教的东西不管用」，通常意味着课程经过了真实项目的打磨。

**最后，几处原文的小瑕疵，整理时我保留未改，但你可以留意：**

- 有一节写「unsloth 框架使用功」，大概是漏了「能」字
- RAG 面试题里第 2 题与第 4 题完全重复
- 团队协作那节「建立 AI 辅助的团队学习文化」重复出现两遍
- LangChain 那节正文写「LECL 构建任务链」，但备注写的是正确的 `LCEL`
- 模块标题的分隔符半角冒号和全角冒号混用（模块 1/3/4/5/6 用 `:`，模块 2/7 用 `：`）

这些都不影响理解，但如果你准备照着课纲做教学或采购，建议先找提供方确认一遍。
