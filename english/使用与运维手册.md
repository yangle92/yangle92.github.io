## 一、应用简介

### 1.1 这是什么

「快乐英语乐园」是一个面向小学生的英语学习网站，覆盖**单词、语法、练习**三大板块。所有数据保存在浏览器本地（localStorage），不需要账号、不需要联网注册，打开即用。

### 1.2 内容规模

| 板块 | 数量 | 说明 |
|------|------|------|
| 单词库 | **310 个单词 / 31 个分类** | 动物、水果、颜色、数字、家庭、职业、动词过去式、反义词等 |
| 语法专题 | **21 个专题** | 从 be 动词、a/an 到比较级、感叹句，每个专题含讲解表格 + 记忆口诀 + 例句 |
| 练习题 | **186 道题** | 单词选择题、各语法专题配套题、综合混合模式 |
| 单词拼写 | **253 个可拼单词** | 看图（emoji）+ 中文 + 音标，字母块拼单词 |

### 1.3 功能特性

- **单词学习**：翻转卡片式学习，点卡片翻面看中文和例句，点 🔊 听发音
- **语法学习**：每个专题含规则表格、记忆口诀、可发音例句，底部有"🎯 做本节练习"直达按钮
- **趣味练习**：单词小测验、🔤 单词拼写、21 个语法专题练习、综合混合模式
- **单词拼写**：支持鼠标点字母块和键盘直接输入，含 💡提示、🧹清空、退格删除
- **语音朗读**：双引擎（系统语音 + 在线真人发音多线路池），自动故障转移
- **激励体系**：星星奖励、学习进度统计、连续学习打卡
- **数据持久化**：星级、已学单词、练习成绩全部存在浏览器本地，关掉再开不丢失

## 二、使用指南（学生 / 家长）

### 2.1 打开方式

**方式 A：直接双击（单机使用）**
在资源管理器中双击 `小学英语学习系统.html`，用 Chrome/Edge 打开即可。

**方式 B：通过本地服务器（推荐，语音更稳定）**
见第三章"发布与运行"。

### 2.2 登录与注册

**首次打开网站会先进入登录界面**，登录成功后才能使用学习内容。

| 项目 | 说明 |
|------|------|
| 首次使用 | 登录页已**禁用自助注册**，需要账号请联系管理员添加（邮箱：821428991@qq.com）；管理员用 admin 登录后，在「后台管理」→「用户」页创建账号 |
| 管理员初始账号 | `admin` / `admin`（**仅记录在本文件中**，页面不再显示，登录后请尽快改密码） |
| 账号名规则 | 2–20 位，可用字母、数字、下划线或中文（不区分大小写，不可与他人重复） |
| 密码规则 | 至少 3 位 |
| 会话保持 | 登录状态保留 7 天，期间打开网站不用重复登录 |
| 退出登录 | 点右上角「👤 用户名 · 退出」按钮 |

**多账号互相独立**：每个账号的学习进度、星星、打卡记录**各自保存，互不影响**。家里有多个孩子时，可以各注册一个账号。首次登录时会自动继承本机的旧学习进度（不会清零）。

### 2.3 数据保存在哪（重要）

账号和学习进度**保存在服务器磁盘**的 `data/users.json`、`data/progress.json` 里，由 `server.py` 负责读写（用 `启动服务器.bat` 启动即是这个模式）。

| 好处 | 说明 |
|------|------|
| 重启服务不丢 | 关闭再打开服务器、重启电脑，账号和进度都在 |
| 换浏览器不丢 | 从 Chrome 换到 Edge，登录同一账号数据一致 |
| 手机电脑共享 | 用手机访问同一台服务器，登录同一账号，进度同步 |
| 改密码处处生效 | 在后台改了密码，所有设备立即用新密码登录 |

> ⚠️ **必须用 `启动服务器.bat`（即 `server.py`）启动才具备持久化能力**。
> 若直接双击 HTML（`file://`）或用纯静态服务器托管，程序会自动回退为「仅存本机浏览器」，
> 此时换浏览器/换设备就看不到了。判断方法：启动窗口里会显示
> `Mode: full server (accounts + progress saved in the data folder)`。

**备份很简单**：把 `data` 文件夹复制走即可（两个 JSON 文件）。恢复时覆盖回去，重启服务生效。

### 2.3 后台管理（仅管理员可见）

用管理员账号登录（初始 `admin`），顶部标签栏会多出「⚙️ 后台管理」；普通账号看不到这个标签。

| 功能页 | 能做什么 |
|--------|---------|
| **👥 用户管理** | 查看全部账号及各自的学习统计（星星/已学单词/练习次数/最近学习）；新增账号（可指定为管理员）、修改任意账号密码、设为/取消管理员、删除账号（会同时清除其学习进度） |
| **📚 单词维护** | 选择分类后可逐条修改单词的图标、英文、音标、中文、例句；支持添加/删除单词行、新建分类、重命名分类、删除整个分类；改完点「💾 保存修改」立即对所有账号生效 |
| **📝 语法维护** | 修改任一语法专题的简介、记忆口诀（一行一条）、例句（可增删改） |
| **🎯 题库维护** | 修改题目：题干、四个选项、用单选按钮指定正确答案、解析文字；可添加/删除题目 |
| **💾 数据备份** | 导出全部数据为 JSON（可选是否含账号）；导入 JSON 恢复；导出「单词库 JS」「题库 JS」文件用于固化修改；清空学习进度 / 清空内容修改 / 恢复出厂设置 |
| **📊 系统信息** | 展示分类数、单词总数、语法专题数、题目数、账号数、内容修改项数量、本地存储占用 |

**内容修改保存在哪？** 浏览器不能直接改写 `js` 文件，所以你的修改存在浏览器本地（键 `happyEnglishOverrides`），页面加载时自动覆盖生效。**要长期固化**：到「💾 数据备份」点「📄 导出单词库 JS」「📄 导出题库 JS」，下载后替换 `js/data-words.js`、`js/data-quiz.js` 即可（替换后记得点「清空内容修改」，避免重复覆盖）。

### 2.4 单词学习

1. 顶部标签栏点击「📚 单词学习」
2. 选择感兴趣的分类（动物、水果、颜色……）
3. 点击卡片翻面，查看中文意思和例句
4. 点 🔊 按钮听单词发音
5. 学过的单词卡片上会显示星星标记，进度自动保存

### 2.5 语法学习

1. 顶部标签栏点击「📖 语法课堂」
2. 选择语法专题（如"be 动词"、"名词复数"）
3. 阅读规则表格和记忆口诀
4. 点击例句旁的 🔊 听标准读音
5. 点「🎯 做本节练习」直接进入该专题的配套练习

### 2.6 趣味练习

1. 顶部标签栏点击「🎮 趣味练习」
2. 选择练习类型：
   - **📖 单词小测验**：看中文选英文 / 看英文选中文
   - **🔤 单词拼写**：看 emoji + 中文 + 音标，拼出单词
   - **各语法专题练习**：针对单个语法点的选择题
   - **🌟 综合模式**：单词 + 语法混合出题
3. 每轮 10 题，答对得星星，结束有成绩结算页

**单词拼写操作技巧：**
- 鼠标：点下方字母块填入，点已填的格子可退回字母
- 键盘：直接打字母输入，退格键 ⌫ 删除
- 卡住了：点 💡 提示一个字母（橙色标记），或 🧹 清空重拼
- 填满自动判分：拼对变绿弹跳，拼错显示正确拼写

### 2.7 学习统计

顶部标签栏「📊 学习统计」可查看：已学单词数、获得星星总数、连续学习打卡天数、各分类学习进度。

- **🔈 试听系统语音**：测试系统自带语音
- **🌐 试听在线发音**：测试在线真人发音
- **✨ 自动 / 仅系统 / 仅在线**：切换引擎模式（一般保持"自动"即可）

## 三、发布与运行（家长 / 运维）

### 3.1 为什么要用本地服务器

直接双击打开（`file://` 方式）功能完整，但：
- 部分浏览器对本地文件的安全限制更严格
- **无法被局域网内其他设备访问**（手机、平板用不了）

通过本地服务器发布后：
- 同一 WiFi 下的手机 / 平板都能访问，孩子用平板学习更方便
- 在线发音线路工作在标准 http 环境，兼容性最好

### 3.2 一键启动（推荐，重启电脑后双击即可）

项目根目录有一个 **`启动服务器.bat`**，双击它就会自动：

1. 找到电脑里可用的 Python（优先 WorkBuddy 自带版 → 系统 `python` → `py` 启动器）
2. 在 `0.0.0.0:8000` 启动服务器（最小化窗口运行）
3. 自动打开浏览器访问 http://localhost:8000/
4. 屏幕上打印出**手机/平板的访问地址**（自动识别局域网 IP）

启动后那个最小化的黑色窗口**不要关**（关了服务就停了）；本窗口 5 秒后自动关闭。

> ⚠️ **改动这个 bat 时注意编码**：它必须以 **ANSI(GBK)** 编码保存，且用 **CRLF** 换行。
> 若用记事本/VS Code 另存为 UTF-8，中文会变成乱码并报「'xxx' 不是内部或外部命令」。
> 用 VS Code 修改时：右下角编码选「GBK」或「Simplified Chinese (GBK)」，换行保持 CRLF。

> 想换端口：把 bat 拖到命令行后加端口号，例如 `启动服务器.bat 8888`。
> 没有 Python 时脚本会给出安装提示，装好 Python（记得勾选 Add to PATH）再双击即可。

### 3.3 手动启动（备用方案）

如果 bat 用不了，可以手动执行（服务器已绑定 `0.0.0.0:8000` 运行，命令如下）：

```bash
cd "C:\Users\yangle\Desktop\作业\english-study"
"C:\Users\yangle\.workbuddy\binaries\python\versions\3.13.12\python.exe" -m http.server 8000 --bind 0.0.0.0
```

> 简化版：系统里装了 Python 的话，在项目文件夹打开命令行执行 `python -m http.server 8000` 效果相同。

### 3.4 访问地址

| 场景 | 地址 |
|------|------|
| 本机访问 | http://localhost:8000/ |
| 局域网访问（手机/平板连同一 WiFi） | **http://192.168.3.17:8000/** |
| 局域网访问（备用网卡） | http://192.168.14.98:8000/ |

> 局域网 IP（192.168.3.17）来自 WiFi 网卡，**路由器重新分配后可能变化**。查询当前 IP：命令行执行 `ipconfig`，看"无线局域网适配器 WLAN"下的 IPv4 地址。

### 3.5 手机访问步骤

1. 手机连接与电脑**相同的 WiFi**
2. 手机浏览器输入 `http://192.168.3.17:8000`（用 bat 启动时，屏幕上会直接显示这个地址）
3. 若打不开 → 见 3.7 防火墙放行

### 3.6 修改端口 / 停止服务

- **换端口**：`启动服务器.bat 8888`（手动启动则改命令中的 `8000`），访问地址同步修改
- **停止服务**：关闭标题为「英语学习系统-服务器(勿关)」的最小化窗口；或在服务器窗口按 `Ctrl + C`
- **开机自启（可选）**：给 `启动服务器.bat` 建个快捷方式，放进启动文件夹（`Win+R` → `shell:startup`）

### 3.7 防火墙放行（手机访问不了时）

首次运行时 Windows 通常会弹窗询问，选择「允许」。若没弹窗或错过：

1. 打开「控制面板 → Windows Defender 防火墙 → 高级设置」
2. 「入站规则」→「新建规则」→「端口」
3. 选 TCP，特定端口填 `8000` → 允许连接 → 全部勾选 → 命名如 "EnglishStudy-8000"

### 3.8 发布到公网（已配置：GitHub Pages）

**当前线上地址：**

| 站点 | 地址 |
|------|------|
| 个人主页（含博客） | <https://yangle92.github.io/> |
| 英语应用 | <https://yangle92.github.io/english/> |

本站已发布到 GitHub Pages，**不需要手动上传文件**，改完内容跑一个脚本就能更新。

| 方案 | 特点 |
|------|------|
| **GitHub Pages**（当前使用） | 免费、稳定、自带 HTTPS；个人主页在根目录，英语应用挂在 `english/` 下 |

#### 更新线上站点

最省事的方式：**双击项目里的 `发布到GitHub.bat`**，一路回车即可。

也可以在命令行执行（等价）：

```bash
# 1. 改完内容后，先在 master 分支提交
git add -A
git commit -m "说明你改了什么"

# 2. 执行一键同步（会自动把改动推 Gitee 备份，再发布到 GitHub）
python sync-to-github.py
```

脚本会自动完成：

1. 切到 `master` 分支
2. 扫描 `C:\Users\yangle\Desktop\BLog`，把文章同步进 `homepage/blog/` 并生成首页清单
3. 有变化就提交并推送到 Gitee（备份）
4. 切到部署分支 `gh-main`，重建个人主页与 `english/` 子目录
5. 推送到 GitHub，然后切回 `master`

推送成功后约 **1~2 分钟**，线上自动更新（无需任何网页操作）。

#### 为什么有两个分支（重要）

| 分支 | 用途 | 目录结构 |
|------|------|----------|
| `master` | 本地开发用，同时备份到 Gitee | 英语项目在**根目录**（双击 `index.html` 即可用）；个人主页源码在 `homepage/` |
| `gh-main` | GitHub Pages 部署用 | 个人主页在**根目录**；英语项目在 `english/` 子目录 |

> ⚠️ **所有修改都在 `master` 分支上做**。不要直接在 `gh-main` 上改——下次同步会被 `master` 的内容整体覆盖。

#### 相关提醒

- 同步脚本依赖 GitHub 的 SSH 密钥（`~/.ssh/id_rsa`），本机已配置好，无需输入密码
- GitHub Pages 是**纯静态**托管，`server.py` 的后端接口不运行 → 账号与进度自动回退到浏览器本地存储，**不跨设备共享**（详见 2.3 节）
- 若手工上传到其它静态托管平台：把 `index.html`、`app.html` 和 `js` 文件夹整体上传即可

### 3.9 个人主页与博客（BLog 自动同步）

个人主页 `https://yangle92.github.io/` 是自己手写的静态页面，由三块组成：**在线应用**、**博客文章**、**技术笔记索引**。

#### 写一篇新文章（两步）

1. 在 `C:\Users\yangle\Desktop\BLog` 里新建一个 `.md` 文件（Markdown 格式），随便命名
2. 双击 `发布到GitHub.bat`（或执行 `python sync-to-github.py`）

1~2 分钟后，文章就会出现在主页的「博客文章」区块。

#### 文章头部元信息（全部可选）

在文件最上方用 `---` 包一段，可以精确控制标题、日期、标签和摘要：

```
---
title: 文章标题
date: 2026-09-19
tags: [运维, Linux]
summary: 显示在首页卡片上的一句话摘要
pinned: true          # 可选：让这篇固定排在首页最前面
---
```

不写也能正常发布，系统按下面的规则兜底：

| 字段 | 不写时的取值规则 |
|------|------------------|
| 标题 | 正文第一个 `#` 标题；再没有就用文件名 |
| 日期 | 文件的修改时间 |
| 标签 | 文件所在的**子文件夹名** |
| 摘要 | 自动截取正文第一段 |

想让它固定排在首页最前面，多写一行 `pinned: true` 就行——详见下面的「置顶文章」小节。

#### 用文件夹做分类

在 `BLog` 里建子文件夹，**文件夹名会自动变成文章的标签**：

```
BLog/
├── 欢迎来到我的博客.md        →  标签：随笔
├── 运维/
│   └── Linux 常用命令.md      →  标签：运维
├── 数据库/
│   └── MySQL 索引笔记.md      →  标签：数据库
└── images/                    →  图片资源，不会当成文章
    └── 截图.png
```

首页会自动出现「全部 / 运维 / 数据库 …」标签按钮，点一下就能筛选，也可以用搜索框按标题、摘要、标签搜索。

#### 图片与附件

`BLog` 里的**所有文件**（图片、PDF 等）都会一起同步过去，相对路径保持不变，所以正文里直接写
`![](images/截图.png)` 就能显示。

#### 资料文档（PPT / PDF / Word / Excel）

把文档直接丢进 `BLog`，同步后首页会多出一张**资料卡片**——点开就能看到要点大纲，直接下载原件。

| 扩展名 | 首页徽标 | 自动提取的大纲 |
|--------|----------|----------------|
| `.pptx` `.ppt` `.ppsx` `.potx` | PPTX | 每一页的标题，按章节分组（如「训练总纲 → 我们的问题全景图」） |
| `.pdf` | PDF | 无，但可在浏览器里直接预览 |
| `.docx` `.doc` | DOCX | 各章节标题 |
| `.xlsx` `.xls` | XLSX | 工作表名 |

规则：

- **标题取文件名**——文件名写清楚就行，想改标题就改文件名再同步一次
- **标签**同样取所在子文件夹名；直接放在 `BLog` 根目录的文档，标签是「资料」
- **页数、体积**自动读取，直接显示在卡片和详情里
- 单文件上限 **25 MB**，超了会跳过，并在同步日志里提示「⚠ 跳过超大文件」
- 大纲是**自动读文档里的文字**得来的，纯图片页不会产生条目，这属于正常现象
- 卡片里的「在线预览」对 PPT/Word/Excel 走微软的在线预览服务，**需要联网**

例子：

```
BLog/
├── 四年级知识强化培训.pptx     →  首页出现资料卡
│                                   PPTX · 共 28 页 · 7.5 MB
│                                   大纲分 6 节：训练总纲 / 卷面与书写 /
│                                   语文模块 / 英语模块 / 数学模块 / 好习惯与总结
└── 教案/
    └── 期末复习提纲.docx       →  标签：教案
```

#### 置顶文章（把某篇固定在首页最前面）

首页默认按日期倒序（最新在前）。想让某篇**固定霸住第一屏**，有两种写法，任选其一。

**写法一：在文章头部加一行 `pinned`**（最省事）

```
---
title: 欢迎来到我的博客
date: 2026-09-19
pinned: true
---
```

**写法二：`置顶清单.txt`**（适合给 PPT / Excel 这种写不了头部的文档置顶）

在 `BLog` 根目录新建一个纯文本文件，文件名就叫 `置顶清单.txt`，一行写一个文件名或相对路径：

```
# 井号开头是注释，空行会被忽略
四年级知识强化培训.pptx
子目录/期末复习提纲.docx
```

不写 `pinned`、写 `pinned: false`、写 `pinned: 0`，都表示不置顶。

**多篇置顶时的先后顺序**

| 情况 | 谁在前面 |
|------|----------|
| 清单文件里的行 | 行权重从 1000 起逐行递减，**越靠上越前**；清单整体优先于 `pinned: true` |
| 都用 `pinned: true` | 仍按日期倒序 |
| 想精细排 | 写数字，数字大的靠前——`pinned: 5` 排在 `pinned: 2` 前面 |

首页上置顶的内容会显示一个红色的「置顶」小徽标（带图钉图标），卡片顶部多一条红色渐变细边；点开后的阅读页顶部也有同样的徽标。

几个要点：

- `置顶清单.txt` 本身**不会**被同步到站点，它只是本地的一份配置，也不计入文章数
- 清单里写了不存在的文件名不会报错，只是不生效（行首带序号如 `1. 讲义.pptx` 也能识别）
- 取消置顶：删掉 `pinned` 那一行（或改成 `false`）再同步一次即可
- 同步日志里会打印一行 `置顶 N 篇：…`，可据此确认是否生效

#### 关于区（关于 & 联系）的布局

规则很简单：**三张信息卡排满一行 + 一条横跨整行的联系条**。

| 屏宽 | 排布 |
|------|------|
| > 1101px | 技术领域 / AI 实践 / 通用能力 三列等宽；「找到我」横跨整行，内部三个联系块各占 1/3 |
| ≤ 1101px | 四张卡按 **2×2** 排满；联系块收窄成只显示平台名（隐藏网址），高度贴住同排的信息卡 |
| ≤ 720px | 单列纵向堆叠；联系块回到「图标 + 平台名 + 网址」的竖排列表 |

> 为什么不用 `auto-fit`：主页容器固定 1120px，`repeat(auto-fit, minmax(300px, 1fr))` 只会排出 3 列，第 4 张卡会掉到第二行独占一格，右侧留一大片空白——这就是之前「没对齐」的原因。现在列数改为显式指定，仅靠 `@media` 断点切换。
>
> 断点为什么是 **1101** 而不是 1000：容器要有 1054px 宽三列才排得下每张 340px 的信息卡。低于这个宽度还硬排三列，卡片会被压到 311px，比全站统一的最小列宽 `--card-min`（320px）还窄，而且同屏的博客 / 笔记区此时已经是两列 474px，滚动起来列宽来回跳。

**加一张信息卡**：在 `homepage/index.html` 的 `.about-grid` 里加一个 `.about-card`（`<h3>` + `<p>`）。注意卡数一旦不是 3 的倍数（或 ≤1101px 下的 2 的倍数），末行又会空出来，需同时调整 `style.css` 里的列数。

**加一个联系平台**：在 `.quick-links` 里照着已有 `<a>` 加一条，`style="--c:#色值"` 控制图标底色：

```html
<a href="https://example.com/you" target="_blank" rel="noopener">
  <span class="ql-ico" style="--c:#0A66C2">IN</span>
  <span class="ql-txt"><b>显示名</b><i>example.com/you</i></span>
```

#### 首页版式与文案约定（改界面之前先看这一节）

**① 文案基调：官方书面语，不用口语**
首屏是访客对站点的第一印象，描述统一按「身份 / 技术方向 / 站点收录范围」三段式写，不用「把踩过的坑写成笔记」「欢迎自取」「现在又多了一条」这类口语。改 `hero-desc` 时注意一个 HTML 细节：**技术方向之间不要有源码换行** —— 换行会在中文里渲染成一个空格，出现「云原生、 数据库」这种缝隙（`.hero-desc` 的整段必须写在一行里）。

**② 首屏描述用平衡断行**
`.hero-desc` 设了 `text-wrap: balance`，让三行长度接近，避免末行只剩「应用。」这种两三个字的孤字行。同时 `.hero-desc b { white-space: nowrap }` 保证「自动化与监控」这类词组不被折成两半。

**③ 全站卡片栅格共用同一个最小列宽 `--card-min: 320px`**
`.app-grid` / `.ai-tracks` / `.blog-grid` / `.notes-grid` 全部写成 `minmax(var(--card-min), 1fr)`。**改列宽只改这一个令牌**，各区块才会在同一屏下保持同一节奏（曾经 AI 区是 300、笔记区是 340，1024px 屏上分别排出 311px 和 475px 两种卡宽，滚动时明显跳动）。

**④ 博客列数会按文章数自适应**
3 列时如果末行只剩 1 张，右侧会空出约 2/3 行的空白。所以 `initBlog()` 会在**「3 列会空 2 格、2 列正好排满」**（文章数 4 / 10 / 16…）时给网格挂上 `blog-grid--duo` 类，切成两列排满：

```js
var duo = list.length >= 4 && list.length % 3 === 1 && list.length % 2 === 0;
grid.classList.toggle('blog-grid--duo', duo);
```

规则在 `apply()` 里，所以**标签筛选 / 搜索之后同样生效**。文章数变化后不需要改代码。

**⑤ 陷阱：`hidden` 属性会被作者样式盖掉**
`.loading` 写了 `display: flex`，特异性高于浏览器默认的 `[hidden] { display: none }`，于是 `#blogLoading` 即使带 `hidden` 也一直显示——首页博客区底部会永远转着三个小圆点。这类问题只靠「看代码」很难发现（DOM 上确实是 `hidden`），是在无头浏览器截图里才看出来的。现在 CSS 顶部统一加了 `[hidden] { display: none !important; }` 兜底。**以后新增任何用 `hidden` 控制显隐的元素，都不用再单独写 `display:none`。**

**⑥ 手机端导航是可横向滑动的**
≤860px 时导航不再整块 `display: none`（那样手机上就没有任何区块跳转入口），改成占满余下宽度、可横向滑动的胶囊条，右侧用 `mask-image` 渐隐提示「还能继续滑」。窄到 480px 时导航会溢出约 60px，属于预期行为。

**⑦ 键盘可跳过导航**
`<a class="skip-link" href="#top">` 放在 `<body>` 第一行，平时藏在视口上方，Tab 聚焦时滑出。

#### 同步常见故障与排查

下面这些坑同步脚本都已经处理过了，以后如果又遇到类似现象，可以对照排查。

| 现象 | 原因 | 处理 |
|------|------|------|
| 卡在 `git push` 十几分钟不动 | 凭据助手在非交互环境下弹出窗口等待输入 | 已修复：禁止一切交互提示，并设 90 秒超时，超时后连同子进程一起结束 |
| 报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 后中断 | 一次性删除的文件数超过环境上限（50 个） | 已修复：改为增量同步，只写内容有差异的文件 |
| 每次都报 `english/ … 新增 8`，但线上并没有变化 | 清理空目录时误删了 `english/js/` 下 8 个文件，随后又被当成新文件重建 | 已修复：删除目录前先确认它真的为空 |
| 每次同步都显示「更新 1」 | 文章源文件是 LF 换行，仓库检出为 CRLF | 已修复：比较内容时忽略换行符差异 |
| 提示「还有未提交的改动」后退出 | `__pycache__` 之类的未跟踪文件被当成改动 | 已写入 `.gitignore`；也可手动删掉该目录 |
| 同步中途失败，仓库停在 `gh-main` | 脚本没能正常收尾 | 执行 `git checkout -f master` 回到开发分支 |
| 放进 `BLog` 的文档没出现在首页 | 文件超过 25 MB，或扩展名不在支持列表里 | 看同步日志有没有「⚠ 跳过超大文件」；把文件压小，或用支持的类型 |
| 资料卡没有要点大纲 | PDF 与纯图片页本来就提不到文字（PPT 若整页是图片同理） | 正常现象，不影响下载 |

**怎么判断同步是正常的**：正常的一轮同步，结尾应该是

```
english/        17 个文件（新增 0，更新 0，删除 0）
站点文件无变化，无需提交
Everything up-to-date
```

三个数字全是 0，就说明本地和线上完全一致。这叫**幂等**——同一份内容反复同步，不会产生任何多余改动；只有你真的改了东西，数字才会变化。

**同步脚本的健壮性设计**：

- **增量镜像**：只写内容有差异的文件，不会整目录重刷，避免「幽灵改动」
- **保护运行产物**：只清理 git 跟踪的文件，`data/`、`dist/` 等本地运行产物不会被误删
- **双超时保护**：普通 git 命令 120 秒、推送 90 秒，超时自动结束整个进程树
- **非交互模式**：通过环境变量禁止任何凭据弹窗，无人值守也能安全退出
- **自动收尾**：无论成功失败，尽量切回 `master` 分支

### 4.4 数据备份与恢复

学习进度存在浏览器 localStorage，**按账号分开存储**：

| 数据 | 存储键 |
|------|--------|
| 账号与密码哈希 | `happyEnglishUsers` |
| 学习进度（某账号） | `happyEnglishDataV2:用户名` |
| 登录会话（7 天） | `happyEnglishSession` |

- **备份**：同一浏览器持续使用即可；换浏览器/清缓存前，可在统计页记录进度，或用浏览器导出 localStorage
- **清零重来**：浏览器按 `F12` → Application（应用）→ Local Storage → 删除对应账号的进度键
- **不同设备之间进度不互通**（各自独立），如需互通需二次开发后端账号系统

### 4.5 账号管理（登录认证）

账号数据存在浏览器 localStorage 的 `happyEnglishUsers` 键中，密码采用**加盐哈希**保存（优先 SHA-256，非明文；同时保存一份 FNV 兜底哈希）。

> 👍 **日常管理建议直接用后台**：管理员登录后到「⚙️ 后台管理 → 👥 用户管理」，可可视化地增删账号、改密码、设管理员、查看每个孩子的学习统计，不必敲命令。下面的控制台方法仅作应急（比如忘记管理员密码）。

> 💡 **为什么存两份哈希**：浏览器的 `crypto.subtle`（SHA-256）只在"安全上下文"可用，即 `https://` 或 `localhost`。当你用手机通过局域网 IP `http://192.168.3.17:8000` 访问时，SHA-256 不可用，程序会自动降级用 FNV 哈希校验。系统同时保存两种哈希，**保证同一个账号在本机、局域网、双击文件三种方式下都能登录**，不会出现"在电脑上注册了账号，手机上却登不进"的情况。

- **查看已注册账号**：控制台执行 `Object.keys(JSON.parse(localStorage.happyEnglishUsers))`
- **忘记密码 / 重置全部账号**：控制台执行
  `localStorage.removeItem('happyEnglishUsers'); location.reload();`
  执行后回到默认状态（admin/admin）
- **删除某个账号**：控制台执行
  ```js
  const u = JSON.parse(localStorage.happyEnglishUsers); delete u['要删的账号名'];
  localStorage.happyEnglishUsers = JSON.stringify(u); location.reload();
  ```
- **新增账号**：用 admin 登录后台管理 →「用户」页，填写账号名和密码即可创建（注册功能已对普通用户关闭）
- **修改默认管理员密码**：admin 登录后台管理 →「用户」页，对该账号执行「重置密码」；或删掉 admin 键后刷新页面，系统会自动重建 admin/admin

> ⚠️ 这是纯前端的本地账号系统，**没有服务端校验**，任何能打开这台电脑浏览器的人都可以用上面的方法重置账号。它的作用是区分不同孩子的学习进度、防止孩子误删数据，不是高等级安全防护。若需要真正的权限管理，需要二次开发后端服务。

## 五、语音问题排查（FAQ）

按以下顺序排查，绝大多数问题在第 1、2 步就能解决：

| 序号 | 现象 | 原因 | 解决办法 |
|------|------|------|---------|
| 1 | 在内置预览面板里点喇叭无反应 | 预览环境 CSP 安全策略拦截外部音频 | **不要用预览面板测语音**，用 localhost:8000 或双击 HTML 打开 |
| 2 | 语音设置面板显示"全部线路红色" | 电脑未联网，或网络拦截了发音接口 | 检查网络；换 WiFi/热点对比 |
| 3 | 系统语音无声（在线发音正常） | Windows 缺英文语音包 | 设置 → 时间和语言 → 语音 → 添加语音 → English (United States)，装好后点「语音设置」里的检测会自动切回 |
| 4 | 页面有声音但很小 | 标签页被静音或系统音量低 | 右键浏览器标签页查看是否静音；调大系统音量 |
| 5 | 偶发某次点击无声 | 线路瞬时故障 | 程序会自动换线路重试；再点一次即可 |

**语音架构说明**（供维护者了解）：
- 引擎 A：系统语音（Web Speech API），离线可用但依赖系统语音包
- 引擎 B：在线真人发音，线路池 3 条（有道词典美音 → 百度 gettts → 有道词典英音），单条失败自动切换，成功线路自动记忆
- 模式"自动"下：先试系统语音（1.3 秒无响应判定失败）→ 自动转在线；选择会记住，下次直接走在线不等待

## 七、技术信息（开发者参考）

- **技术栈**：原生 HTML5 + CSS3 + JavaScript（ES2017），零依赖、零构建
- **脚本加载**：经典 `<script src>`（非 ES module），`file://` 与 `http://` 均可运行
- **存储**：localStorage（学习进度键 `happyEnglishDataV2:用户名`；账号键 `happyEnglishUsers`；旧版键 `englishLearningData` 的进度会自动迁移）
- **认证**：`js/auth.js` —— 前端登录认证，密码 SHA-256 加盐哈希（`crypto.subtle`，不可用时 FNV-1a 四轮兜底），默认管理员 `admin/admin`，会话 7 天，登出按钮动态注入 header
- **单词进度 key**：`${分类key}:${单词下标}`（v3 之前带年级前缀，已做兼容迁移）
- **持久化架构**：`server.py`（Python 标准库，零依赖）提供静态服务 + `/api/users`、`/api/progress` 两组接口；账号与进度以 JSON 存于 `data/`，采用**原子写入**（临时文件 + `os.replace`）与 `threading.Lock` 防并发损坏；进度合并以 `updatedAt` 时间戳「新者胜出」避免旧设备覆盖新数据。前端 `js/sync.js` 负责检测与双向同步，**接口不可用时自动回退 localStorage**
- **接口一览**：`GET /api/health`（探测）、`GET|POST /api/users`（账号；值为 `null` 表示删除，admin 受保护，缺 `hash`/`salt` 的脏数据会被过滤）、`GET|POST /api/progress`（进度）
- **自动化测试**：`.workbuddy/test-spell.js`（拼写全流程）、`.workbuddy/test-speech.js` / `test-speech2.js`（语音引擎切换 27 项）、`.workbuddy/test-auth.js`（登录认证 39 项）、`.workbuddy/test-admin.js`（后台管理 41 项）、`.workbuddy/test-server-api.js`（服务端接口 26 项）、`.workbuddy/test-sync.js`（前后端同步 18 项），用 Node 运行：`node --check js/*.js` 校验语法
- **个人主页相关测试**：`.workbuddy/test-homepage-dom.js`（主页在 jsdom 中的真实渲染 149 项，笔记数与分组从 `blog-data.js` 推导、博客期望值从 `blog/index.json` 推导，加减内容无需改测试；末尾 §12 是一组**布局与文案守卫**——jsdom 不做布局计算，所以那里守的是「版式决策本身」，如栅格是否共用 `--card-min`、`[hidden]` 兜底规则在不在、博客列数类是否按文章数挂对）、`.workbuddy/test-blog-md.js`（自研 Markdown 渲染器 41 项）、`.workbuddy/test-blog-sync.py`（博客扫描 / 附件大纲提取 / 置顶 / 清单生成 / 增量镜像 / 换行归一化 / 目录清理 / 推送超时 139 项）
- **⚠️ jsdom 测试必须拦截资源请求**：jsdom 的 `resources: "usable"` 会按 `url` 选项去**线上**抓 `assets/*.js|css`，于是只有 `index.html` 是本地文件、脚本全来自已部署的线上站——本地改动根本测不到（表现为「改了本地代码测试却依然全绿」，极易误判）。现在用 jsdom 30 的 `requestInterceptor()` 把同源请求映射回本地 `homepage/` 目录，测试才真正跑本地代码。升级 jsdom 时注意：30.x 已不再导出 `ResourceLoader`，改用 `resources: { interceptors: [requestInterceptor(fn)] }`
- **主页版式的三条约定（改界面之前必读，详见 §3.9）**：① 所有卡片栅格统一写 `minmax(var(--card-min), 1fr)`，**改列宽只改 `--card-min` 这一个令牌**，各区块同屏节奏才不会错位；② ≤860px 时导航是「可横向滑动的胶囊条」而不是 `display:none`（否则手机上没有任何区块跳转入口）；③ CSS 顶部有 `[hidden] { display: none !important; }` 兜底 —— 因为作者样式里的 `display:flex`（如 `.loading`）特异性高于 UA 的 `[hidden]{display:none}`，会让 `#blogLoading` 即使带 `hidden` 也常驻显示（这问题**只在无头浏览器截图里看得出来**，DOM 上确实是 `hidden`）。另外：居中首屏描述用 `text-wrap: balance`，`.hero-desc` 整段源码必须写在一行（换行会渲染成中文里的空格）
- **AI 实践区块**：`homepage/assets/blog-data.js` 的 `window.AI_DATA` 定义 6 个能力方向（`tracks`，含 `icon`/`level`/`desc`/`tools`）与等级→刻度映射（`levels`）；`app.js` 的 `initAI()` 渲染方向卡，并按 `matchTags` / `matchRe` 从 `POSTS` 自动筛出「实践产出」（文章在前、资料在后，各自按日期倒序，用稳定排序保证同日保持清单原序）。因为产出依赖博客清单，`initBlog()` 返回 Promise，`boot()` 用 `initBlog().then(initAI)` 串联
- **置顶机制**：`scan_blog()` 把置顶落成 `pinned: true` + `pinOrder`（数字，越大越靠前）两个字段，仅置顶项才写，普通文章不带这两个键。来源有两处——Markdown 的 front matter（键名 `pinned` / `pin` / `sticky` / `top` / `置顶` 任选，值是 `true`、数字或任意非空词），以及 `BLog` 根目录的 `置顶清单.txt`（每行一个文件名或相对路径，权重从 `PIN_BASE_ORDER` = 1000 逐行递减，因此**清单顺序优先于 front matter**）。排序做法是「先按日期倒序，再把置顶项稳定上浮并按 `pinOrder` 降序」，所以同为 `pinned: true` 的多篇之间仍保持日期序。两份清单文件名（`置顶清单.txt` / `pinned.txt`）在扫描阶段就被跳过，既不镜像也不出卡片
- **附件资料机制**：`scan_blog()` 遇到非 Markdown 的文档（`ATTACH_KINDS`：pptx/ppt/ppsx/potx、pdf、docx/doc、xlsx/xls）会生成 `kind: "file"` 的资料卡片，字段含 `fileLabel`/`fileKind`/`fileName`/`fileSize(Text)`/`pageCount`/`outlineLabel`/`outline`；大纲用**标准库**解析 OOXML 得到——PPTX 按 `<a:p>` 段落合并 run 后逐页取标题，章节名靠「独立成行的章节名 ∩ 正文页开头的『编号 章节名』」双重确认（避免「21 天行动表」这类含数字标题被误判）；DOCX 取标题段落，XLSX 列工作表名。解析失败一律降级为「只有下载」，不影响同步
- **双分支发布机制**：`master` 是开发分支，存放源码与运维脚本（同步备份到 Gitee）；`gh-main` 是发布分支，内容为「把 `homepage/` 提到仓库根目录」后的站点产物 + `english/`（英语应用完整副本）。`sync-to-github.py` 把 `gh-main` 推送到 GitHub 的 `main`，GitHub Pages 从 `main` 构建
- **同步幂等性**：`sync_tree()` 按文件内容增量比对，并忽略 CRLF/LF 差异，因此同一份内容反复同步不会产生改动（正常输出为「新增 0，更新 0，删除 0」）；删除操作只作用于 git 跟踪的文件，且清理目录前先判空
- **内容修改机制**：浏览器无法改写 js 文件，后台的内容修改存于 `happyEnglishOverrides`，加载时由 `Admin.applyOverrides()` 覆盖内存数据；「导出 JS」可把修改固化为 `data-words.js` / `data-quiz.js`
- **⚠️ 全局挂载约定**：`const` 声明不会自动成为 `window` 属性，`auth.js` / `admin.js` 末尾必须显式 `window.Auth = Auth;` / `window.Admin = Admin;`；否则 app.js 里的 `window.Auth` 判断全部失效（账号隔离与后台面板都会失灵）
- **浏览器兼容**：Chrome / Edge（推荐）、Firefox、Safari（含 iOS，已做手势解锁）
