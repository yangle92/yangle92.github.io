## v9：修复启动 bat 乱码（重要教训）

用户双击 bat 报 `'ORT' 不是内部或外部命令`、中文乱码。**两个叠加原因**：

1. **编码错（主因）**：bat 被写成 UTF-8，而 cmd.exe 用系统 ANSI 码页（中文 Windows = GBK/936）解析脚本 → 中文被解成乱码并当成命令执行。文件内写 `chcp 65001` 无济于事（解析时乱码已产生）。
   **正确做法**：bat 文件本身必须以 GBK 编码保存，并 `chcp 936`。
   **转换方法**（PowerShell，避免含 cmd 语法被安全校验拦截）：
   ```powershell
   $t=[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)
   [IO.File]::WriteAllBytes($p,[Text.Encoding]::GetEncoding(936).GetBytes($t))
   ```
2. **换行符错**：编辑工具写出的文件是 LF，bat 需要 CRLF（多行 `if (...)` 块在 LF 下可能解析异常）。用 Node 以 latin1 读写做 `.replace(/\n/g,'\r\n')` 转换，不破坏中文字节。

**校验方法**（Node，full-ICU 支持）：`new TextDecoder('gbk').decode(buf)` 检查中文完整、无 BOM、UTF-8 解码应出现 U+FFFD（反证已是 GBK）。
另：ipconfig 取 IP 的解析逻辑已用真实输出验证（跳过 127.0.0.1 后取首个 → 192.168.3.17）。
手册 3.2 已加「改 bat 必须保持 GBK + CRLF」的警告。

## v10：系统英文语音包下载（诊断结论，重要）

用户要求"下载系统语音包"。诊断结果揭示了 Chrome 无声的真正根因：

1. **SAPI 传统语音**：`HKLM:\SOFTWARE\Microsoft\Speech\Voices\Tokens` 里有 `TTS_MS_EN-US_ZIRA_11.0`（Microsoft Zira Desktop - English US）——英文语音"看起来"是装了的

3. **结论**：Chrome/Chromium 的 Web Speech API 只枚举 OneCore 语音，不认老的 SAPI "Desktop" 语音 → `speechSynthesis.getVoices()` 拿不到英文音色 → 系统语音播英文无声。这解释了为什么用户"装了英文语音包"却依然没声音。系统语言只有 zh-Hans-CN。
4. **修复**：安装 `Language.Speech~~~en-US~0.0.1.0` 功能包（约 100MB）。当前账户属管理员组但未提升，非提权调用报"请求的操作需要提升"。
5. **工具限制**：PowerShell 工具禁止 `Start-Process -Verb RunAs` 提权（安全策略：shell/LOLBin 目标绕过校验），也禁止 COM 实例化（SAPI.SpVoice 读不了，只能用注册表查语音）。故改为提供 `安装英文语音包.bat`（GBK+CRLF，含 `net session` 管理员检测），用户右键"以管理员身份运行"。

**复用要点**：
- 查系统语音：`HKLM:\SOFTWARE\Microsoft\Speech_OneCore\Voices\Tokens`（Chrome 用）与 `...\Speech\Voices\Tokens`（老 SAPI）——**两者不一致是 Chrome 无声的典型原因**

## v11：账号与进度持久化到服务器磁盘（重要架构变更）

用户要求"管理账号和密码要持久化，不能 http 服务重启后失效"。

**诊断**：账号本就存 localStorage，重启服务不会丢。真正原因是 **localStorage 按来源(origin)隔离**——内置预览面板(127.0.0.1:随机端口)、localhost:8000、手机 192.168.x.x:8000、file:// 各是各的存储桶，换一种打开方式就像"全部重置"，且手机与电脑永远无法共享账号。

**方案**：把数据落到服务器磁盘。

1. **新增 `server.py`**（Python 标准库，零依赖，替代 `python -m http.server`）
   - `ThreadingMixIn` 多线程（浏览器多连接，单线程会阻塞）+ `allow_reuse_address`
   - 接口：`GET /api/health` 探测、`GET|POST /api/users`、`GET|POST /api/progress`
   - 数据存 `data/users.json`、`data/progress.json`；**原子写入**（tmp + os.fsync + os.replace）+ `threading.Lock`
   - 服务端防护：值为 `null` = 删除（admin 不可删）；缺 `hash`/`salt` 的脏数据过滤；进度按 `updatedAt` 新者胜出，防旧设备覆盖新数据
   - 已验证：kill 服务 → 换端口重启 → 账号/哈希/进度全部保留 ✅
2. **新增 `js/sync.js`**：`Remote` 模块，3s 超时的 fetch 封装，任何失败静默返回 null。**接口不可用（file://、纯静态托管）自动回退 localStorage，功能不受影响**
3. **`auth.js`**：新增 `syncFromServer()`（init 时调用：服务端有本地没有→拉下；不一致→以服务端为准；本地有服务端没有→上传迁移）、`pushAll()`、`pushDelete(name)`（发 null，否则删掉的账号重启后会"复活"）。createUser/resetPassword/setRole/deleteUser 后均回写
